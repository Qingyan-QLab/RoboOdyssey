# Benchmark 运行与评分规则

本页集中维护执行顺序、运行时修补、成功判定、计分与诊断口径。
安装和命令见 [README](../README.md)，配置及进程管理见 [LAUNCH](LAUNCH.md)，
消息字段见 [PROTOCOL](PROTOCOL.md)，日志和报告路径见 [OUTPUTS](OUTPUTS.md)。

<a id="scope"></a>
## 1. 适用范围与职责

规则适用于 **dataset schema 5 / layout 2 / contextual_requests version 3**。
数据版本、任务契约版本和输出目录布局版本相互独立；应读取 manifest，不能根据目录名推断。
数据读取和执行仅接受上述发布契约。

Builder 负责生成与冻结任务顺序、语言模板、名称、依赖、mutation 计划及参考 GT。
Benchmark 不重新生成任务，负责真实执行、状态回读、按冻结契约修补、记录证据和评分。
模板表达式及修补语义由归档内的冻结 language_catalog／templates 与 Benchmark 的
[运行契约实现](../roboodyssey/contracts/contextual.py) 共同约束；数据字段见 [发布数据契约](DATA_FORMAT.md)。源归档保持只读，实际 GT 与执行证据写入新的运行目录。

<a id="execution"></a>
## 2. 执行单位、连续性与预算

- **序列**是一次连续评测单位。按归档的 Session 顺序、各 Session 的 Task 顺序执行；v5 禁止截取 Session、Task 或任务类型。
- 同一序列只初始化一次场景，跨 Task／Session 保留真实世界、机器人位姿、执行历史、名称账本和 Agent 记忆。任务失败不会回滚世界，也不会自动跳过后续任务。
- 不同序列使用独立进程和初始状态。带 sequence_id 的归档要求 Agent 确认新 run_id 的记忆重置；本地及外部服务记忆都须清空或按 run_id 隔离。具体握手字段见协议。
- 每个 Session 开始时处理其冻结 mutation；按真实状态与绑定经历判断是否可施加，并回读结果。记录 ready／skipped／not_applied 及实际变化；不把计划变化当作已经发生，后续请求使用回读状态。
- 每个 Task 下发前重新读取权威状态并修补。可执行时进入“观测 → Agent 响应 → 动作 → 回读 → 判定”循环，结束后记录真实开始／结束状态与结果。

| 项目 | 当前规则 |
|---|---|
| 步数 | 默认每 Task 最多 **2000 次 step 循环**，多目标共享预算，v5 问答也在该循环内；不是每个目标各 2000 步 |
| 一步的含义 | 一次响应中的移动、转向、观察、no_op、reset 或失败动作尝试都占该轮；日志 `steps` 是实际写入的动作事件数，unsupported 等提前返回可能没有动作事件 |
| 超时 | 默认每次 Agent 请求 **120 秒**，不是整个任务的总时限 |
| 结束 | 满足完整 GT、Agent 返回 done、环境终止／截断、达到步数上限或明确 unsupported；done 本身不是成功证据 |
| 中断 | 接入／运行异常进入错误收尾；当前不支持从中断日志恢复连续评测，重跑须创建新运行 |
| 情境时间 | “昨天”等指代依据归档的 issued_at／current_time；它与实际运行耗时、视频时间分开 |

<a id="observations"></a>
### 真实时间 2 FPS 观测

新运行的任务观测按**真实时间每 0.5 秒**调度一次，用单调时钟固定采样时刻。
每次采到图像立即发给 Agent；等待动作响应期间也发送，不把推理耗时加到下一次发送间隔里。
任务切换沿用时钟；任务外的加载、介绍和 mutation 阶段不计入采样窗口。

Benchmark 不设置待发送图像缓存，不替换或丢弃已经采到的帧。新一轮 step 携带该时刻的图像，
其余采样时刻发送独立的 observation 消息，无需等待回复；同时最多有一个动作请求等待响应。
例如 t=0 的图推理到 t=1.2 才返回，t=0.5、1.0 的图仍已发送给 Agent；执行动作后 t=1.5 的图随下一轮请求发送。
Agent 须持续接收观测，模型何时推理、如何维护图像记忆是 Agent 的策略；发送 2 FPS 不要求每帧都输出动作。
发送端只使用正常管道传输，若接收端不读导致一次发送超过 0.5 秒，按接入错误中断，不另设队列或偷偷丢帧。

每个动作响应须关联请求及所依据的 observation_frame_id。
不能用其后才送达的帧替之前的答案补证据。接收线程收到图像不等于模型已经用它推理，
也不等于已识别目标；示例适配器明确以本次模型输入快照对应的帧号返回。新版问答只按答案正确性评分，
不要求实例分割、可见像素或距离取证；正常 RGB 观测仍按相同调度发送，取图失败仍是运行异常。

Isaac 渲染仍在主线程完成。渲染、动作或其他主线程操作超过采样期限时，跳过错过的时刻，
记录漏采和延迟，不补造一串旧时刻或声称严格达到 2 FPS。相机取图失败按运行异常处理。
每次采样完成新的 RGB 渲染；采图本身不推进重力／接触求解，避免世界状态无故漂移。
这项设置没有把高层移动改成持续速度控制：**2000 步仍是动作循环预算，不等于 1000 秒真实时间**。

该调度覆盖 step 的任务观测。HoloAgent 专用 ROS 传感器、GUI 刷新和事件录像采用各自机制，不由此帧率控制。
采样策略写入 run_config 和 evaluation_profile 哈希，实际采样及发送时间保存在日志中。
时间字段及采样审计格式见 [PROTOCOL](PROTOCOL.md#观测与时间) 和 [OUTPUTS](OUTPUTS.md#session-原始证据)。

Agent 只接收公开指令、名称介绍、情境时间、允许动作、普通观测和自己的记忆。
GT、私有对象／区域操作 ID、权威附近物体清单、实例像素、修补记录和 overview 不作为 Agent 输入。
抓取使用已介绍的公开名称，运行器私下解析到对象；消息结构和动作编码只在协议文档维护。

<a id="official"></a>
### 正式配置与诊断配置

通用 `run --official` 会先校验数据，并强制：完整所选序列、无 Scene／Session／Task／类型筛选、
headless、无人工 step delay、每任务 2000 步、每请求超时 120 秒、水平视场角 100°，
禁用录像及 HoloAgent 专用 ROS 传感器。该配置的前视相机分辨率为 256×256。
数据哈希、相机／动作参数、序列身份及 evaluation_profile 哈希随运行保存。

普通 `run` 可作诊断并修改预算。当前 SimpleNav `experiment` 入口生成普通运行，
即使手动关闭 GUI／录像，也不会自动设置 official；正式标志以保存的 run_config 为准。
GUI、事件采样录像及私有受控动作实验用于诊断；受控实验不能并入模型成绩。
正式任务分、`official` 配置标志、`evaluation_valid` 和进程完成状态是不同概念。

<a id="repair"></a>
## 3. 运行时修补、名称与真实历史

修补依据是**实际世界状态和真实经历与冻结计划的差异**。保持原目标身份、原历史绑定和合法语义顺序，
不因任务失败、能力不支持或模型可能遗忘而降低记忆要求。

- 已下发的名称介绍视为已经告知；失败和 unsupported 不撤销账本。后续继续使用名称，不能重新展开属性作为提示。
- 只有首次介绍确实未下发，后续首次有效使用时才补介绍。已满足／不可下发的决定不等于名称介绍，也不创造执行经历。
- 名称之外仍成立的冻结描述保持原文；只有位置关系等失真才改相应描述。仅答案或目标几何变化时，只刷新私有 GT。
- 搬运失败后可保存未拿起、仍持有、放错区域等实际状态。“任务开始／结束时在哪”使用原绑定任务的真实快照；需要位置经历的引用还须有相应经历证据。
- 命名地点在真实到达时建立，回访绑定实际建立的位置，不随参照物后来移动。建立失败时不能改成普通物体导航来取消记忆要求。
- 不能从计划 GT 或当前状态倒推缺失历史；缺失／冲突快照、绑定或契约错误属于证据／接入问题。

来源因 `already_satisfied` 未下发时没有真实请求经历，按归档内冻结的 fallback 转换并记录 conversions：

| 后续依赖 | 转换方式 |
|---|---|
| room_before、room_after、has_changed 等历史问答 | 转成 current_room，使用当前观察要求与当前答案，移除虚构的历史／变化检测要求 |
| 搬往来源 before／after 区域 | 使用来源未下发决策时的真实区域作目的地，并改用普通搬运表述 |
| 以该来源作对象指代的搬运／访问 | 使用允许的普通搬运／访问 fallback，保留原目标及多目标顺序 |
| 命名地点回访 | 建立地点任务不能被判 already_satisfied；出现这种来源记录属于契约错误 |

前序已经失败时，只有合法修补后仍无法解析原身份／原经历，并具有 `failure_causes` 因果证据，
才允许 unavailable。来源关联本身不等于失败因果；具体排除与异常处理见下文。

<a id="scoring"></a>
## 4. 成功条件与任务评分

评分使用**修补后的 runtime_ground_truth 和实际执行证据**。离线“前序全部成功”的参考位置不再作为当前目标。
一个 Task 的所有目标及要求的顺序全部满足才成功。成功标志与下面的连续任务分分别保存；失败也可以有部分分。

| 目标 | 成功条件 |
|---|---|
| visit | 某个有效位姿样本到运行时目标二维包围盒的距离 ≤ GT 容差（缺省 0.8 m） |
| 有序多目标 | 按目标列表依次到达；后一个目标必须使用严格更晚的位姿样本，提前路过不算完成；已完成的访问不会因后来离开而撤销 |
| establish_place | 达到目标范围，以真实到达位姿建立地点（当前实现保存以该点为中心、各轴 ±0.05 m 的区域） |
| revisit_place | 到来源实际建立的固定地点范围，不是参照物当前所在位置 |
| transfer | 目标在运行时目的区域、已释放、包围盒底面距该区域地面 ≤0.04 m，且本任务有该对象的成功 place 事件；仅持物进入区域不算成功 |
| answer | 只检查答案是否匹配运行时 accepted_answers／布尔值；不要求当前观察，不以动作过程决定得分 |

新版所有问答（包括 NOW／CHANGE 和历史回忆）仅按答案正确性判成功和计分，归档内的 inspection_contract
不再作为评分门槛。答案仍匹配任务下发时修补后的实际 GT；不会因后续动作而重写标准答案。
问答接口允许移动、转向、调整视角和 no_op；pick、place、open、close、reset 请求会被拦截并反馈，
仍占该轮预算，但不因该尝试强制失败或扣分，同一响应中的答案照常判断。

v3 区域答案按大小写、标点、空白归一化后匹配公开名称；允许 `the …`、`in …`、`in the …`、
`it is in the …` 包装，不接受私有区域 ID 或任意包含答案的长文本。布尔回答只允许 yes／true
或 no／false 一侧出现，正反同时出现不能得分。答案使用确定性判断。

<a id="exclusions"></a>
### 成功、失败、排除与运行无效

| 情况 | 逐任务正式分 | 分母与运行处理 |
|---|---:|---|
| 满足完整实际 GT | 导航／搬运按进展及效率计分；问答目标得 100 | 计分，完整成功单独记 true |
| 普通执行失败、达到步数上限或提前 done 时未满足 GT | 导航／搬运可得过程分；错误问答目标得 0，多目标取均值 | 计分，保留真实状态继续后续任务 |
| Agent 明确 unsupported，包括不支持问答／搬运 | 0 | 计分；不是 unavailable |
| already_satisfied | N/A | 下发前可证明整个请求已满足；不下发，从分子／分母排除 |
| unavailable | N/A | 合法修补仍不可执行且有前序失败因果证据；不下发并记录排除原因 |
| 接入错误、响应超时／格式错误、异常中断、缺失任务结果／顺序不一致 | 不生成有效的整体正式分 | `evaluation_valid=false`、汇总 `task_score=null`；不能排除错误任务后对剩余任务宣称有效成绩 |

already_satisfied 当前只适用于**单目标** visit／revisit_place／transfer：导航已在达标范围，
或搬运目标已在目的区域地面并释放。此时不要求一个未下发任务产生 place 事件。
问答、建立命名地点、有序多目标仍需真实执行；未知状态不能证明已满足。
无合法排除记录的未执行任务不能从分母悄悄消失。分析保留已完成任务的结果，但不会把异常整次运行重新认证为有效。

### 任务分：progress_path_v3

新 schema 5／契约 3 运行使用 `progress_path_v3`，每个任务满分统一为 **100**。
任务分为必要目标分的算术平均，成功率仍按完整 GT 统计，不能由得分是否等于 100 推断成功。
**导航目标**（visit／establish_place／revisit_place）：开始任务前保存真实碰撞网格、原点、分辨率和机器人半径，
按环境碰撞规则处理开门；若前序搬运失败后仍持物，也保存物体对关闭门的额外通行半径。
目标使用修补后的 GT 合格区域。距离用八邻域带权 Dijkstra，直边长一格、斜边长 √2 格，禁止切过墙角。
这是与实际碰撞地图绑定的**网格近似距离**，不是精确连续最短路或 Isaac navmesh 距离。
仅连接当前位置附近可直达的网格中心，不把机器人或目标自动挪到墙另一侧。

```text
当前目标进展 p = clip(1 − 当前网格距离 / 该目标激活时的网格距离, 0, 1)
有序进展 P = (已完成导航目标数 + 当前目标进展) / 导航目标数
D0 = 真实起点经过所有导航目标合格区域、遵守顺序的最短网格路线
R = 当前点经过尚未完成目标的最短网格路线
C = 实际行走长度 + reset 计费长度
路径效率 E = D0 / max(D0, C + R)
导航组得分 = 100 × P × E
```

后一个目标激活基准取前一个目标的真实到达位置；同一样本只完成一个目标，新激活目标须使用更晚样本。
提前经过后续目标不贡献分数，已完成的访问保留。最短有序路线由目标区域之间的反向动态规划计算，
不采用逐段挑最近端点的贪心路线。正式分使用最终进展；最佳进展／最佳路径调整分只作诊断。
为逐目标平均，每个完成导航目标记 `100×E`，当前目标记 `100×p×E`，其余记 0。

例如 A→B→C 已完成 A，B 激活时距其合格范围 8 m，结束时剩 2 m，则 p=0.75、P=(1+0.75)/3。
尚未完成的目标接近后又远离，会降低最终进展；已完成的访问保留。导航规则
不引入阶段权重或额外固定罚分。

每次已执行 reset 按 `max(两端点最短网格距离, 实际传送位移, 一格长度)` 计费；
即使原地 reset 也至少计一格，次数及传送位移另存，不能把传送归为正常行走。
绕路增大 C，进而通过 C+R 降低路径效率；reset 以等效路径长度加入 C，而非每次任意扣固定分。
此成本不保证每次 reset 都严格扣分：若 C+R 未超过 D0，E 仍为 1，必须结合传送辅助指标解释成绩。
转向、原地碰撞、等待没有额外的路径成本；动作步数与真实耗时另列，不冒充路径效率。
D0 为零时，仅 C 和 R 同时为零才令 E=1，否则为 0；当前目标激活距离为零时，在合格范围内才有该目标进展。
缺少可达目标网格中心、路线不可达、任务中改变地图／目标、轨迹不连续或参考缺失时，路径评分为 null 并记录原因，
保留任务和成功结果，不能把该任务从分母删除或换用直线距离悄悄计分。

**搬运目标**：按“还需多少工作才能完整交付”计算连续进展，乘以执行成本效率，不设固定阶段权重：

```text
J0 = 从实际任务初始状态完成交付的最小参考成本
J = 从实际最终状态完成交付的最小剩余参考成本
P = clip(1 − J / J0, 0, 1)
C = (实际行走长度 + reset 计费长度) / 标准移动步长 + pick/place 尝试次数
E = J0 / max(J0, C + J)
搬运目标分 = 100 × P × E
```

成本单位是**等效动作数**：距离除以本次环境配置的 `move_step`（默认 0.25 m），
每次抓取和放下尝试各计 1，包括失败和重复尝试。长距离单次移动仍按真实距离换算，
不因合并动作而降低成本。转向、观察和等待不额外计费；reset 使用上面的等效路径规则后除以步长。
这是公开冻结的评分计量约定，不是实际最少 step 数、耗时或物理能量。

未持有目标时，参考成本包括接近合法抓取位置、抓取、运送、合法放下；
持有目标时只包括剩余运送和放下。使用反向带权最短路联合选择抓取位置与后续运送路线，
不贪心选择最近抓取点。抓取范围按真实对象原点及环境的 1.5 m 半径判断；
拿起后移除目标原占据，其他障碍物保留。释放后按真实包围盒重建占据，持物时沿用环境的通行半径。

合法放置位置同时检查机器人所在区域、朝向偏移后的对象中心区域和落地高度，
使用环境实际的前方 0.8 m 放置偏移、对象原点到包围盒的偏移及地面参数。
网格参考枚举 72 个等间隔朝向，当前位置额外检查真实朝向；这是位置／朝向采样的近似参考，
不是精确连续配置空间最优解。最终是否成功仍以真实 GT 和本任务成功 place 事件为准。

例如接近需 10、运送需 20 个移动单位，加上抓取／放下各 1，则 J0=32。
最优路径接近一半时 P=5/32，拿起时 P=11/32，持物送达但未放下时 P=31/32，
完整交付时 P=1。最终分还乘 E，绕路完成可以低于 100；未放下至少剩一个必要操作，不能拿满分。
接近后远离会失去进展；放错、掉落、重新拿起或放回原处时，按最终真实状态重新计算接近／抓取／运送／放下成本，
不会永久保留“曾经拿起”的阶段分。阶段条件仍作为诊断证据保存。

搬运参考保存真实对象原点、可移除占据、房间标签、地面、动作参数及任务开始状态，附 SHA-256。
逐动作另存实际碰撞网格及通行半径的前后哈希，复算须与动态重建的参考一致；
对象原点、持物状态、抓放事件和真实位姿也须互相吻合。
当前冻结模板的搬运均为单目标，参考支持已验证的 all-open-doors 环境；不将单目标成本套用于未支持的联合多物体任务。
起始路线不可达、缺少原点／地图／状态变化、持有无关物体、背景世界改变或真实抓放与参考机制不符时，
目标分为 null 并记录原因，保留分母。执行后剩余路线确实不可达时进展与效率为 0。

**问答目标**：仅答案正确记 **100**，错误或未回答记 **0**。没有观察分、距离／可见性门槛或动作过程扣分；
答对但未观察仍记 100，观察充分但答错仍记 0。unsupported 统一记 0；多目标任务仍按各必要目标平均。

动作数、请求次数、任务真实耗时、等待 Agent 耗时及动作执行耗时独立保存。任务耗时从开始执行到结果判定，
包含观测等待、推理和运行器开销，不包含前置参考地图准备。没有已验证的 GT 步数和真实耗时基准时，
step_efficiency_score／time_efficiency_score 为 N/A；不把 2 FPS 换算为固定动作耗时，不设置任意时间权重。
参考快照与 SHA-256、评分版本和测量结果写入新运行，离线分析可复算并比对，不改历史原始证据。

<a id="rescoring"></a>
### 离线复算与参考重建

普通 `analyze` 复算当前运行保存的评分并核对一致性。显式 `--rescore` 将重新计算的指标写入独立报告，
保留原始结果、分数和来源字段。它不改变实际执行的成功／失败，也不覆盖原始日志。

导航参考缺失时，可使用 `--reference-dataset` 指定与记录的 manifest SHA-256 一致的发布数据，
根据真实下发前状态重建导航网格。重建结果标记 `original_live_snapshot=false`，不冒充原始现场快照。
该功能仅适用于可验证的导航参考；缺失完整搬运成本快照时，搬运分保持 null。

日志中可验证的任务单调时间跨度和 Agent 请求／响应往返耗时可独立统计，缺少动作计时不补写。

<a id="aggregation"></a>
### 汇总口径

- 新版单个有效 Session／序列：`score_100 = 计分任务的部分任务分均值`，`task_score=score_100/100` 保持 JSON 的 0–1 尺度；页面与逐任务统一显示 0–100。`task_success_rate` 单独统计成功数／计分数。
- 任一计分任务缺少新评分证据时，整体 score_100／task_score 为 null、metrics_complete=false，并列出 tasks_missing_metric；该任务仍在分母，成功率仍可统计。接入错误则使整次运行 evaluation_valid=false。
- Session 的 success 为其全部计分任务成功；全部排除时为 null。序列 task_score 按全部计分任务汇总，不先平均各 Session。
- 能力分组只统计计分任务；同一任务可进入多个 capability 分组，因此分组数量不能直接相加当作总任务数。
- 集合／实验按同评分版本的**有数值分数的序列等权平均**，不是将所有序列任务混在一起平均。零分母序列保留但不参与数值平均；任一子运行失败／缺失／无效、评分证据不全或版本混用，整体分数为 null。
- 同时报告 tasks_total、tasks_evaluated、tasks_excluded 及排除原因。读取分数时应同时检查运行有效性和分母。

当前 v5 的辅助 `session_success_rate` 按全部 Session 数作分母，全部排除的 Session 不计成功但仍在该分母中；
`sessions_evaluated` 则只数有计分任务的 Session。任务分与 Session 统计分别使用各自明确的分母。

<a id="diagnostics"></a>
## 5. 导航进度、路径、碰撞与恢复诊断

本节保留包围盒几何距离、碰撞与恢复诊断，和上面的网格路径任务分分别展示。诊断从当次日志读取实际 GT、位姿、目标顺序和结果；
校验下发记录、动作数、样本连续性、逐目标证据与 Session metrics，并记录来源哈希。
缺失或矛盾证据列为错误，不补零，不重新生成任务。仅纯 visit／establish_place／revisit_place
任务有导航进度；排除项没有执行进度。任务中目标发生移动时，静态目标距离诊断会明确报不适用。

### 距离与进度

距离 d 为机器人 XY 点到运行时目标包围盒的欧氏距离，回访采用实际建立的固定范围。
它与评分器的 aabb_2d 口径一致，**不是导航网格最短路径距离**，也不能证明模型识别了目标。
逐目标报告任务起点距离、最终距离、全程最近距离，以及该目标按序激活后的起点／最近距离。

令容差为 t，剩余距离 r=max(d−t,0)，该段起点剩余距离为 r_start：

```text
单目标进度 = 100 × clip(1 − r / r_start, 0, 1)
r_start = 0 时：在达标范围内为 100，否则为 0
有序多目标进度 = 100 × (已按序完成目标数 + 当前目标进度 / 100) / 目标数
```

后续目标以前一目标实际到达点为该段起点，同一样本不能又完成下一个目标；未激活目标不贡献进度。
最终进度取有序进度曲线末值，最佳进度取全曲线最大值，不相加各目标不同时间的最佳值。
完成的目标保持完成；最终进度不等于单纯比较结束位置与第一个目标的距离。

### 路径、碰撞、reset

| 指标 | 定义 |
|---|---|
| 行走长度 | 非 reset 动作前后 XY 位移之和；是记录样本间的位移，不是逐物理帧的精细轨迹 |
| reset 传送长度 | reset 动作前后 XY 位移单列，不加入行走长度，也不插值成行走路径 |
| 碰撞次数／率 | 次数为 collision=true 的动作条数；主率为发生碰撞的平移动作数 / 平移动作数，另存全动作率；零分母或标记缺失为 N/A |
| reset 次数 | 导航诊断要求 reset_applied=true；请求次数另存。Session 原始 reset_count 是运行器发起合法 reset 的计数，核验实际恢复时使用动作回读 |
| 行走效率 | 仅成功、无已执行 reset 且距离下界非零时计算：各有序段起点到达标范围的直线距离下界之和 / 行走长度，上限 1；其余 N/A。它不是 SPL 或可通行最短路径效率 |

合法 reset 将机器人送回环境保存的起始／安全位姿，不重置任务、步数预算、世界物体或记忆；
每次 reset 仍占一轮动作。问答的动作限制见成功条件，GUI 手动 reset 在 v5 中禁用。
导航成功及进度会使用合法 reset 后的真实位置，因此须同时报告传送辅助，不能归为正常行走能力。
新版路径任务分计入 reset 的等效路径成本；碰撞次数不再额外叠加任意罚分。

每次 reset 固定比较当时的当前目标；恢复窗口在下一次 reset、该目标按序达标或任务结束时截止。
记录复位前、刚复位后、恢复阶段最近和阶段末距离，以及前后行走／碰撞情况；分别计算传送接近量、
后续行走接近量、净接近量和是否靠行走刷新此前最佳距离。分类区分复位直接达标、复位后行走达标、
仅传送变近和未获得更近位置，不单凭最终距离改善断言已有效解困。

失败标签可重叠：始终未进入近达标带、接近但未达标、接近后离开、多目标只完成部分、反复碰撞／reset。
近达标带默认是容差外 0.5 m，`--near-margin-m` 只改变诊断标签；反复碰撞／reset 的阈值为至少两次。
这些标签描述几何和动作现象，不把“始终远”解释成已经证明模型没找到目标。
